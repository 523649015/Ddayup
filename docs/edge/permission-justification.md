# Ddayup 网页素材采集扩展 — 权限用途说明（Edge 商店提交用）

本说明逐项解释扩展在 `manifest.json` 中申请的权限，证明其均为实现「网页素材采集」核心功能所必需，且无超出必要范围的请求。

## host_permissions: `<all_urls>`
扩展需要扫描**任意网站**上的图片、视频、音效、3D 模型等素材，因此必须对用户访问的所有页面具备读取与注入能力。这是素材采集功能的根本前提。

## permissions

| 权限 | 用途 |
|---|---|
| `activeTab` | 仅在用户主动点击扩展、对当前标签页操作时临时获取该页访问权，用于扫描当前页面素材。 |
| `scripting` | 向页面注入素材扫描脚本（如解析 `<video>`/`audio`、提取资源 URL），是采集逻辑的执行基础。 |
| `storage` | 保存设备标识、授权状态、扫描结果与用户偏好等本地数据（`chrome.storage.local`）。 |
| `downloads` | 将用户主动选择的素材（图片/视频/音效/模型）下载到本机，是「下载到本地」功能所需。 |
| `sidePanel` | 扩展主界面以 Edge 侧边栏形式呈现（Chrome/Edge 通用），提升多任务采集体验。 |
| `webRequest` / `webNavigation` | 监听页面网络请求与导航，捕获通过流媒体/接口动态加载、DOM 扫描难以发现的真实素材直链（如视频分片、音频播放 url）。 |
| `declarativeNetRequest` / `declarativeNetRequestWithHostAccess` | 在下载受保护视频/音频时，自动注入必要的 `Referer` 请求头规则，使浏览器下载 API 能正确获取源站资源（绕过 403）。属本地请求改写，不收集数据。 |
| `cookies` | 部分源站（如需要登录态的音频/视频托管）要求携带会话 Cookie 才能拉取媒体；扩展仅在本地为这些请求附加必要 Cookie，不会读取或外传 Cookie 内容。 |
| `clipboardWrite` | 提供「复制图片到剪贴板」功能，便于用户将采集到的图片直接粘贴到微信 / Photoshop 等外部应用。 |
| `tabs` | 定位当前/源页面标签页，以便把素材导入到对应页面或回源刷新直链。 |

## externally_connectable: `http://127.0.0.1:3000/*`、`http://localhost:3000/*`
仅允许**本机运行的 Ddayup 后端 / 网页应用**与扩展通信，用于「导入素材到 Ddayup 素材库」与授权状态查询。不连接任何外部域名。

## 隐私承诺
所有权限均在本地、用户主动操作（扫描/下载/导入）时生效；扩展不后台静默采集、不上传数据到第三方、不含广告或追踪代码。详见同目录 `privacy-policy.md`。
