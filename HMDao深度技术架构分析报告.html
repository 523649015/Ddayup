一、执行摘要

本报告基于对 HMDao 项目全部 56 个源代码文件的逐行审查、运行时浏览器验证、以及联网搜索对标竞品的最新技术信息，进行全面深度诊断。共发现 18 项功能未落实、12 个隐藏 Bug，涉及数据流转断裂、内存泄漏、性能瓶颈、以及架构级缺失。

最严重问题（P0）：
  1. Undo/Redo 功能伪实现 — 有 history 状态但 undo/redo 只是移动指针，不恢复画布状态
  2. 所有 Toolbar 工具按钮 action 为空函数 — 剪辑/解析/音频分离/下载全部无响应
  3. SmartAgent 意图检测仅关键词匹配 — 无 LLM 调用，无法处理真实自然语言
  4. Three.js 面板重复创建 WebGL 上下文 — 快速切换导致内存泄漏和浏览器崩溃
  5. 缺少后端服务层 — 纯前端静态部署，所有 AI 生成功能为 UI 占位
已实现亮点：
  1. 8 个节点类型全部注册并渲染，UI 风格统一
  2. Three.js PBR + IBL 3D 打光面板（真实 3D 渲染，非 CSS 模拟）
  3. Three.js OrbitControls 多角度编辑器（3D 球体 + 环绕控制）
  4. Canvas 2D 帧级剪辑时间线（选中区域高亮 + 时长计算）
  5. NodeErrorBoundary 单节点崩溃隔离
  6. Agentic Workflow 引擎（9 个预设模板 + 意图匹配 + 自动节点编排）

3.2 核心能力差距分析

差距一：后端服务层完全缺失（P0）

当前 HMDao 是纯前端静态部署（dist/ 文件夹直接部署到 CDN），所有数据存储在 Zustand 内存中。页面刷新后所有画布数据丢失；无法调用任何 AI 模型 API；无法实现用户注册/登录/权限管理；无法保存和分享工作流。

差距二：Undo/Redo 功能伪实现（P0）

代码中有 history 数组和 historyIndex，但 undo() 和 redo() 仅移动指针，没有根据历史记录恢复画布状态。用户点击撤销/重做按钮无任何效果。

差距三：AI 模型接入链路未打通（P0）

文本节点的"GVLM 3.1"、图片节点的"Lib Navi Pro"、视频节点的"Kling O3"、音频节点的"Minimax"均为纯文本标签。需要打通 ComfyUI API：/prompt 提交 + /ws WebSocket 进度推送 + /history/{prompt_id} 结果获取。

差距四：Toolbar 工具全为占位（P0）

Toolbar.tsx 第 14-21 行，所有 6 个工具按钮的 action 均为 () => {} 空函数。剪辑/捕捉帧/解析/音频分离/视频修复/下载全部点击无响应。

差距五：Three.js 内存泄漏（P1）

ImageNode 的打光/多角度面板每次打开都创建新的 WebGLRenderer、Scene、Mesh。快速切换（点击打光 → 多角度 → 打光）会创建多个 WebGL 上下文，在低端设备上导致 GPU 内存耗尽和浏览器崩溃。虽然已添加 dispose cleanup，但缺少"单例模式"确保只有一个活跃场景。

差距六：SmartAgent 无 LLM 调用（P1）

SmartAgent.tsx 第 209-220 行，意图检测仅通过 input.toLowerCase().includes(kw) 关键词匹配。无 LLM API 调用，无法处理模糊表达、多意图、上下文理解。

差距七：缺少复制/粘贴/框选（P1）

无法 Ctrl+C/V 复制节点，无法 Shift+拖拽框选多个节点，无法批量操作。这在 10+ 节点的工作流中严重降低效率。

差距八：导入/导出无 UI 入口（P2）

useCanvasStore 中有 exportCanvas() 和 importCanvas() 实现，但 Toolbar 中没有导出/导入按钮，功能完全不可见。

Bug #1 详细分析：Undo/Redo 伪实现

问题代码（useCanvasStore.ts:372-384）： 
undo: () => {
  set((state) => {
    if (state.historyIndex < 0) return;
    state.historyIndex--;  // 仅移动指针，不恢复状态
  });
},
redo: () => {
  set((state) => {
    if (state.historyIndex >= state.history.length - 1) return;
    state.historyIndex++;  // 仅移动指针，不恢复状态
  });
},
根因：history 只记录操作类型（add/remove），不记录操作前的完整状态快照，也不存储逆向操作。因此移动指针后无法恢复画布。 修复：采用 Command Pattern，每个操作同时存储"执行"和"撤销"函数，撤销时调用逆向操作。

Bug #3 详细分析：WebGL 上下文泄漏

问题代码（ImageNode.tsx 3D 面板）： 
// 每次 subState 变为 'lighting' 时都创建新场景
useEffect(() => {
  const renderer = new THREE.WebGLRenderer({ canvas, antialias: true });
  const scene = new THREE.Scene();
  // ... 创建 geometry, material, mesh
  return () => {
    // cleanup 存在但面板切换时旧场景可能未完全销毁
    cancelAnimationFrame(raf);
    controls.dispose();
    renderer.dispose();
  };
}, []);
根因：useEffect 依赖项为 []（仅挂载时运行），但组件可能因父组件重渲染而卸载/重新挂载。此外，打光面板和多角度面板同时存在时可能创建两个 WebGL 上下文。 修复：使用 ref 缓存 renderer/scene，切换面板时主动销毁；限制最大 WebGL 上下文数为 1。

6.4 智能体 (Agent) 系统

技术选型：LangGraph 2026

根据 2026 年最新对比（LangGraph v1.0 vs CrewAI vs AutoGen）：

  • LangGraph：图状态机架构，适合画布这种节点-边拓扑结构，支持 checkpoint/rollback/human-in-the-loop
  • CrewAI：角色团队协作，适合内容创作pipeline
  • 推荐方案：LangGraph 为主（画布工作流编排）+ CrewAI 为辅（内容创作子任务）

Agent 核心交互流程

用户自然语言 → 意图识别（LangGraph Node: intent_classifier）
  → 任务拆解（Node: task_planner）→ 工作流规划（Node: workflow_builder）
  → 画布自动构建（Node: canvas_executor）→ 参数填充（Node: param_injector）
  → 逐段执行（Node: step_runner）→ 结果汇总（Node: result_aggregator）
  → 用户确认（Human-in-the-loop Checkpoint）

十三、AI 生成链路专项分析

本章回答五个核心问题：（1）填写 API Key 能否激活节点大模型？（2）输入提示词能否生成图片/视频？（3）8G 显存能否 1 分钟生成 15S 视频？（4）会报错还是一直等待？（5）流程上需要补充什么？

13.1 当前状态：填写 API Key 能激活吗？

答案：不能。当前状态分析：
  1. HMDao 是纯前端静态部署，没有后端服务
  2. 即使在前端代码中硬编码了 fal.ai、OpenAI 等 provider 名称，但没有实际的 API 调用逻辑
  3. 所有节点上的模型标签（GVLM 3.1 / Lib Navi Pro / Kling O3 / Minimax）均为纯文本占位
  4. 用户在节点 AI 面板中输入提示词并点击发送按钮 → 无任何网络请求发出
  5. 没有 API Key 输入界面，没有 API Key 存储机制

13.2 要实现生成链路，需要补充什么？

完整生成链路需要以下 6 个环节全部打通：

AI 生成链路全景（前端 → 后端代理 → 云 API）

13.3 为什么需要后端代理？不能直接前端调用吗？

问题说明解决方案
CORS 跨域限制fal.ai / Replicate 等云 API 不允许浏览器端直接调用（安全策略）后端代理转发请求
API Key 暴露风险前端代码中 API Key 可被用户查看，存在泄露风险后端存储 + 请求头注入

大文件传输生成的视频文件可能几十 MB，需要断点续传后端流式下载 + CDN 回传

13.8 生成链路技术实现方案

前端请求代码示例

// 用户点击发送按钮时调用
async function generateContent(nodeId: string, params: GenerateParams) {
  const apiKey = await getEncryptedApiKey(params.provider); // 从 localStorage 解密
  
  setNodeStatus(nodeId, 'generating'); // 显示 loading
  
  try {
    const res = await fetch('/api/generate', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ ...params, apiKey }),
    });
    
    if (!res.ok) {
      const err = await res.json();
      if (err.code === 'INSUFFICIENT_CREDIT') 
        showToast('API Key 余额不足，请充值');
      throw new Error(err.message);
    }
    
    const data = await res.json();
    updateNodeOutput(nodeId, data.url); // 显示生成结果
    setNodeStatus(nodeId, 'completed');
  } catch (e) {
    setNodeStatus(nodeId, 'error');
    showToast(`生成失败: ${e.message}`);
  }
}

后端代理代码示例

// Node.js Express 代理
app.post('/api/generate', async (req, res) => {
  const { provider, model, prompt, width, height, duration, apiKey } = req.body;
  
  try {
    // 根据 provider 路由到不同云 API
    const result = await routeToProvider(provider, {
      model, prompt, width, height, duration,
      api_key: apiKey, // 注入用户 API Key
    });
    
    res.json({ url: result.url, duration: result.duration });
  } catch (err) {
    if (err.status === 402) 
      res.status(402).json({ code: 'INSUFFICIENT_CREDIT' });
    else 
      res.status(500).json({ message: err.message });
  }
});
